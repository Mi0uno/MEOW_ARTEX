# MEOW_ARTEX 项目记忆

> ⚠️ **2026-09-29 起演示 PG 已迁至 5498**（新集群 `out/pgdemo-cluster2`）；5499 被另一项目（竞赛平台 arena_* 数据）占用，不要对 5499 跑测试。详见文末「2026-09-29 批次优化与环境剧变」。

## 项目定位
AI 自主渗透平台（`D:\AI\MEOW_ARTEX`，github.com/Autumn-27/artex）。Go 1.26 单体 + Next.js 16 静态导出内嵌（go:embed `server/webui/dist`），PostgreSQL。三阶段扩展已建：信息搜集(recon) / 渗透测试(exploit) / 后渗透(post)。

## 构建与部署（关键流程）
- 唯一正确构建方式：`GOSUMDB="sum.golang.org" ./build-local.sh out/artex-local`（自动 next build → **拷贝 web/out → server/webui/dist** → go build -tags embedui）。GOSUMDB 必须设置否则工具链下载失败。⚠️ **重建前必须先停 8787 实例**（Stop-Process 8787 的 PID）再 build——exe 被运行进程锁定时 go build 静默失败（BUILD=1 但只看 grep「部署完成」容易漏）。正确顺序：停进程 → build → 启动。
- ⚠️ **实例 exe 位置会漂移，动手前必须 `netstat -ano` + `Get-CimInstance Win32_Process` 核实**（2026-09-28 实测：8787=`out/artex-local/artex.exe`，由仓库根 start-bg.vbs 守护拉起；8799=`out/artex-verify/artex.exe`，**无守护**——杀掉不会自动重生，要手动重启）。升级 8787 的零中断套路：构建到 out/artex-verify 后，把新 exe 拷进 out/artex-local（运行中 exe 不能覆盖但**可以改名**：`mv artex.exe artex.exe.bak-<日期>` 再拷入新的），然后杀进程让 vbs 守护用新 exe 拉起（项目自带 one-click update 路径）。
- ⚠️ 内嵌的是 `server/webui/dist` 拷贝目录，不是 web/out —— next build 后忘拷贝 = 浏览器永远旧包（踩过）。
- webui HTTP 头已修：HTML `no-cache`、`_next/static/` immutable（webui_embed.go）——发版即生效，不再依赖用户强刷。
- 运行：`ARTEX_PG_DSN=postgres://postgres@127.0.0.1:5499/postgres?sslmode=disable ./out/artex-local/artex.exe -addr 127.0.0.1:8799 -data ./out/data`。`-data` 必须显式指定，默认跟可执行目录走（换目录=丢数据/丢 blob）。
