# He 的协作风格（MEOW_ARTEX 长期协作沉淀）

## 本体复用（最高优先级，多轮被打回后固化）
- **字面复用，拒绝仿品**：说"复用X页面"= 路由直指X页面+参数锁定，或抽共享组件双路由薄壳（`?stage=recon` 模式已验证）。做仿品/长得像的独立版会被打回（工具页/企业详情页/字典库各被打回过）。
- 正确模式：原页面 + useSearchParams 锁定参数 + Suspense + 锁定时隐藏筛选器 + 锁定时换对应新建按钮。
- 组件抽取是可以的（如 TaskDetailView 抽出后双路由共享），但必须**就是同一份代码**，不是重新实现。
- 他会说"跟 xxx 一样的图程序嘛"来指认应该复用哪个——注意听他指的是哪个页面/组件。

## 拒绝壳子（多次被打回）
- "只做了个壳子"/"敷衍" = 功能没有端到端真实可用。tool seed 无 handler、有卡片没绑定、有 API 没前端页面，都算。
- 每轮交付必须**全链路可验收**：API 通、前端页可操作、数据流完整。
- 他会问"做XX了吗"来抽查——如果只做了后端没做前端、或只做了壳，他会发现。

## 验收习惯
- 开浏览器 → 肉眼检查 → 点按钮 → 报 bug（含截图）
- 改完没生效时按序查：服务端 chunk 内容 → 缓存头 → 浏览器缓存（webui 已加 no-cache 后应绝迹）
- 他会给出工作正常的页面 URL 作为参照（"跟 xxx 一样的图程序嘛"）——对比差异找根因比盲猜快。

## 沟通偏好
- 验收截图配短句（"这个图咋又出bug了"、"怎么还没修好"），不需要道歉，需要立刻定位+修复+说清根因。
- 中文交流；功能命名用中文标签（信息搜集/渗透测试/后渗透）。
- 他会给官方文档链接——SPA 登录墙抓不到时明说"需要登录后复制原文给我"，别硬编。
- 多说"记录清楚" = 把踩坑教训写进代码注释，防止重犯。
- 说"开始做"/"启动" = 立刻动手实现/启动服务，不是讨论方案。
- 简短消息"继续" = 当前工作流程继续推进（构建/部署/下一步），不需要确认。
- "修不好就换思路" = 如果某个技术方案反复被卡（如 Mimosa 拦截），果断换实现路径，不要反复试同一种方法。

## 二进制名与部署
- 二进制名是 **MEOWFUCK.exe**（GUI 版，windowsgui 子系统，不弹终端窗口），不是 artex.exe。build-local.sh 两个都产。
- 用户说"以后都是MEOWFUCK没有artex" = 统一用 MEOWFUCK 品牌。

## 部署管线（踩过多次）
- `build-local.sh` 是唯一正确构建（自动同步 web/out → server/webui/dist + go build embedui）。
- 手动 `next build` 不拷贝 dist = 浏览器永远旧包（踩过，修了 webui 缓存头后此问题应绝迹）。
- 端口约定：**8799 = 开发/演示**，8787 = 用户自己的实例，永远不占。

## 演示/环境偏好
- 一次性演示环境（独立 PG 集群 + 独立端口）随起随用，不碰他的正库和 8787。
- 演示数据要预埋到位（企业/资产/任务现成可看），他打开就验收，不现场配。
- 他会直接说"启动开发服务器"来要求起服务——起完给 URL + 登录凭据 + 预埋数据清单。
